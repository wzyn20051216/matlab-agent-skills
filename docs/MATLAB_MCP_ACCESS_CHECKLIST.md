## 2. 什么才算 R2/R3 的证据

必须同时满足：

1. 会话的工具清单里出现 `mcp__matlab*` 名字的工具；
2. 智能体在本次会话中**实际调用**了它，且调用出现在执行记录里；
3. 该调用产生的结果（数值或文件）与 `bench_boost_task.m` 的验收条件一致；
4. 记录里能读出调用次数与耗时。

**不算证据**：

- 阅读 `SKILL.md` 之后手写脚本（那是 R1）；
- 用 `matlab -batch` 执行并声称"通过 MCP"；
- 引用其它会话（例如 2026-10-17）的 `PASS L5` 报告；
- 只证明服务器进程能启动，没有任何一次工具调用。

## 3. 接入步骤（下一次具备条件时按序执行）

1. **确认服务器可启动。** 本机已装 MATLAB MCP Server Toolbox；按其文档给出的启动方式
   运起服务进程，确认它监听成功。
2. **绑定到客户端。** 在客户端的连接器管理里新增一个自定义 MCP 连接器，指向该进程。
   绑定后**必须重新列出工具**，确认出现 `mcp__matlab*`。
3. **单点连通性测试。** 先做一个只读调用（例如求值 `1+1`），确认往返正常。
4. **跑基准任务。** 用 `bench_boost_task` 完全相同的自然语言规格发起任务，禁止在
   prompt 里附带实现步骤；让被测路线自己决定怎么写。
5. **记录。** 保存：prompt 原文、工具调用清单（名称+次数）、执行耗时、脚本内容、
   是否首次执行即通过、最终数值是否满足 `|vOut-48|/48 ≤ 0.5 %`。
6. **对照。** 与 R1 的 `b2_task4_bench.json` 逐字段比较；差异要能解释。

## 4. R3 额外需要的条件

R3 比 R2 多一层：**技能必须被真正触发**，而不是被读懂。

- 仓库里的 `skills/*/SKILL.md` 是 Codex 格式文档，共 9 个；
- 要成为 R3，它们必须被客户端作为可调用技能索引，并且在任务开始时由系统**自动加载**
  （记录里应有技能名与加载时刻），而不是智能体手工 `Read` 之后照做；
- 只有当"自动加载记录 + MATLAB MCP 调用记录"同时存在，R3 才成立。
